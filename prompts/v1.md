# Prompt versions

## v1 (first working version)

Same as v2 below, except rule (4) read:

> (4) due_date must be YYYY-MM-DD, resolved from the meeting date (for example 'jeudi' or 'la semaine prochaine' relative to the meeting date), otherwise null.

**What went wrong:** for "on envoie la relance la semaine prochaine" the model invented a precise
date (2026-10-09). The speaker never named a day, so that date is a guess presented as a fact.

## v2 (current, `prompts/system_prompt.txt`)

Rule (4) now says: if the deadline is vague, approximate or only a period ("la semaine
prochaine", "bientôt", "dès que possible"), use `null` and keep the original wording in the
task text. A date is only used when a specific day or date is stated or clearly implied
("demain", "jeudi", "le 7 octobre", "lundi").

**What it fixed:** no more invented due dates. Vague deadlines stay readable in the task text
("... l'envoyer la semaine prochaine") instead of becoming a fake date.

Other rules that were in v1 and are unchanged:
1. Only record what was actually said.
2. Reversed decisions: keep only the final one.
3. `owner` must be a person named in the transcript, otherwise `null`.
5. Cancelled actions must not appear.
6. Unowned items go in `actions` with `owner: null`; unresolved topics go in `open_questions`.
